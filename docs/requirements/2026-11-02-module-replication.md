# 模块复刻规则（2026-11-02 用户确认）

## 核心要求
1. 每个模块开始前，在 GitHub 搜索该主题 star 数最高的项目，记录项目名、star、链接、许可证、选择理由。
2. 以最高星项目为基准复刻核心能力；理解后重写，不直接 fork 或整仓复制源码。
3. 复杂度下限：一个完整闭环（输入 → 执行 → 结果 → 可视化/报告），禁止 Hello World、纯 CRUD demo。
4. 每个模块交付：可运行代码、验收网页、原理说明、使用步骤、最终效果（截图/报告/指标）。
5. 验收网页统一挂在最终展示站/测试平台，模块完成后必须能在线访问。
6. 对外笔记放 `docs/notes/<module>/`，验收页放平台。
7. 选型与 star 记录维护在 `docs/requirements/module-matrix.md`。

## 模块检索方向
| 模块 | 检索关键词 | 选型标准 |
|---|---|---|
| 01 方法论 | awesome testing / software testing roadmap | 体系完整、可转成方法论文档与检查表 |
| 02 Python 测试开发 | python testing / pytest | 核心机制可复刻，能体现 fixture、参数化、报告 |
| 03 接口自动化 | api testing | 能复刻请求构建、集合、环境、断言、批量执行、报告 |
| 04 Web 自动化 | web automation / playwright / cypress | 能复刻浏览器驱动、元素定位、录制或回放、报告 |
| 05 App UI 自动化 | appium / mobile testing | 能复刻会话管理、元素定位、手势、设备管理 |
| 06 性能测试 | load testing / k6 / locust | 能复刻压测编排、并发模型、指标采集、可视化 |
| 07 测试平台 | test management platform | 能复刻用例管理、计划、执行、缺陷、报表闭环 |
| 08 Agent/LLM 评测 | llm evaluation / ragas / promptfoo | 能复刻数据集、评测指标、对比、报告 |

## 验收页统一结构
每个模块页面至少包含：项目背景与最高星参考、复刻范围与取舍、架构图、原理说明、使用步骤、运行截图/报告、指标或效果对比、踩坑记录、源码入口。

## 执行纪律
- 不为了“看起来复杂”堆无意义功能；复杂度来自真实闭环和数据流。
- 每个模块先写验收标准，再写代码。
- 模块未达到验收标准前，不标记完成。
