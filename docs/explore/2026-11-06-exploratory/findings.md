# 探索式测试发现清单 · AI 测试平台

- 系统：AI 测试平台（`http://127.0.0.1:8000/ui/`，版本 v1.2.0）
- 角色设定：第一次用它的普通运营 / 新测试同学
- 时间：2026-11-06，约 10 分钟，走查 25 个视图（17 个新路由 + 9 个「开发工具」旧页 + 若干弹窗/窄屏/键盘状态）
- 方式：Playwright 驱动真实 Chromium，逐页扫「可点可填的入口」再试；只做导航、开关弹窗、输入、空提交（有前端校验、不落库）
- **未执行**（会产生真实副作用，按要求只记录）：发送调试请求、执行用例、AI 生成、上传附件、删除、保存任何表单

原始记录：`pass1.json`（路由扫描）、`pass2.json`（表单/项目记忆/窄屏）、`pass3.json`（弹窗/键盘/长输入）、`pass4.json`（焦点/刷新/跳转），截图在 `shots/`。

---

## 一、高优先级（会直接卡住或让人不信任）

### 1. 新建需求点「确定」没反应，也看不到错误

- **现象**：标题留空直接点「确定」，弹窗不动、页面无任何提示。
- **复现**：需求管理 → 右上「新建需求」→ 不填任何内容 → 点「确定」。
- **判断**：代码里确实做了空标题校验，但错误提示 `<p class="alert error">` 渲染在弹窗**外面**的页面顶部，被 `.modal-mask` 遮住。新用户的第一反应是「按钮坏了 / 页面卡死」，很可能连点几次然后放弃。
- **严重程度**：高（表单第一入口）。

### 2. 概览页数字自相矛盾，口径不明

- **现象**：hero 写着「项目 #— 的整体状态」，但下面 4 个项目 / 44 用例 / 4 计划 / 2 执行全是**全平台聚合**；更奇怪的是「执行记录 2」配「通过率 75%」——2 条执行里 1 通过 1 失败，怎么算都是 50%，不可能是 75%。
- **复现**：打开 `#/overview`；或 `GET /api/platform/summary`，返回 `executions: 2, pass_rate: 0.75`。
- **判断**：`pass_rate` 实际按**用例结果条数**统计（3/4），卡片文案却写「最近 10 次执行」。数字对不上，用户会怀疑整个平台的数据可信度；「项目 #—」这个占位符也没告诉人现在是全平台视图。
- **严重程度**：高（数据可信度）。

### 3. 旧版页面与新版功能同名并存，分不清哪套是现在用的

- **现象**：侧栏底部「开发工具」展开后有 10 个入口：仪表盘、工单管理、API 工作台、知识库问答、测试平台、模型中心、测试用例、方法论、项目报告、模块验收。它们的样式与新菜单**完全一样**，且功能与新版重叠：

  | 旧入口 | 新版对应 |
  | --- | --- |
  | 知识库问答 `/knowledge` | 知识库 `/kb` |
  | 测试平台 `/platform` | 项目概览 `/overview` |
  | 测试用例 `/testcases` | 功能测试 `/functional` |
  | 模型中心 `/models` | 系统 AI 配置 `/system-ai` |

- **复现**：点「开发工具」→ 依次点「知识库问答」「测试平台」「测试用例」。
- **判断**：新用户会以为「知识库有两个」，或者在旧页面里建数据，然后在新页面找不到。旧页面至少需要「旧版」标签或直接下线。
- **严重程度**：高（认知负担 + 数据分叉）。

### 4. 404 页的「返回仪表盘」把人送回旧版

- **现象**：随便输个不存在的地址（如 `#/project-overview`）→「页面不存在」→ 唯一按钮「返回仪表盘」→ 落到**旧版仪表盘**，不是新版「项目概览」。
- **复现**：地址栏改成 `#/project-overview` 回车 → 点「返回仪表盘」。注意侧栏「项目概览」的真实路由是 `/overview`，所以这个 404 很容易被手输 URL 的用户撞到。
- **判断**：迷路的人被送到一个更旧、更陌生的页面，等于二次劝退。
- **严重程度**：高（虽然触发需要手输 URL，但一旦触发就是死路感）。

## 二、中优先级（能用，但会让人犹豫或白等）

### 5. 环境管理点进去是「规划中」

- **现象**：侧栏有入口，点进去只有一块「规划中的能力」清单，右上角标着 **Phase 4**（当前已是 Phase 5），还写着 `skill: environment.list / environment.create`——这两个 skill 在「项目概览 → 平台能力」里根本不存在。
- **复现**：自动化 → 环境管理。
- **判断**：用户以为功能坏了，或者去 skill 列表里找一个不存在的 id。空态应该写「下一阶段提供」并隐藏假的 skill 名，阶段号也别留旧的。
- **严重程度**：中。

### 6. 弹窗按 Esc 关不掉

- **现象**：知识库「分块」弹窗打开后按 Esc 无反应；点遮罩可以关。
- **复现**：知识库 → 任一行「分块」→ 按 Esc（弹窗仍在）→ 点空白遮罩（关闭）。
- **判断**：键盘用户的标准预期是 Esc 关闭，这里失效；连续开几个弹窗后容易迷失。
- **严重程度**：中。

### 7. 键盘焦点环看不见

- **现象**：按 Tab 时焦点确实在移动，但焦点框是 `outline: rgb(16,16,16) 1px`——深灰黑色，落在深色侧栏和深色表格上几乎不可见。
- **复现**：任意页按 2 次 Tab，观察侧栏第二项。
- **判断**：不点鼠标就没法知道自己在哪，键盘/读屏用户基本不可用。
- **严重程度**：中。

### 8. 「刷新状态」按钮全站都有，但没人知道它刷了什么

- **现象**：每个页面右上角都有「刷新状态」，点击后无 loading 停留、无 toast、无「最后更新时间」，数据也没明显变化。
- **复现**：项目管理 → 点「刷新状态」。
- **判断**：文案含糊（状态？数据？连接？），点击零反馈，用户会反复点或干脆不信它。
- **严重程度**：中。

### 9. 「单接口 Agent」没选接口也能点生成

- **现象**：切到「单接口 Agent」，接口下拉为空，但「AI 生成用例」按钮是可用状态（`disabled=false`）。
- **复现**：接口自动化 → 单接口 Agent → 直接观察按钮。
- **判断**：点了必然报错或空转，等于让用户白等一次模型调用。应在未选接口时禁用并给一句「先选一个接口」。
- **严重程度**：中。

### 10. 各页「当前项目」默认值不一致，常落到空项目

- **现象**：接口自动化 / UI 自动化会记住上次选择（localStorage），但模块管理、成员管理每次打开都取列表第一个项目；项目排序按名称，结果默认落在「自动化测试项目」（0 模块），页面一片「还没有模块」。
- **复现**：模块管理 → 首次打开（或清 localStorage）→ 显示 0 条，需要手动切项目才有内容。
- **判断**：用户会以为「我的模块没了」。应统一用「上次选择 / 最近有数据的项目」作为默认。
- **严重程度**：中。

## 三、低优先级（打磨项）

### 11. 调试抽屉的 Base URL 是空的

- **现象**：「接口管理 → 调试」抽屉里 Base URL 输入框为空，虽然服务端会回退到接口资产或项目的 base_url，但界面没提示「留空即用资产地址」。
- **判断**：新用户不知道要不要填、填什么，容易自己拼错地址后归因到接口本身。
- **严重程度**：低。

### 12. 超长搜索词没有约束

- **现象**：往「搜索标题或模块」里塞 200 字，输入框不截断、不提示，列表直接空。
- **判断**：不算 bug，但没有「最多 N 字」或「无匹配」的更明确文案时，用户会怀疑是搜索坏了。
- **严重程度**：低。

### 13. 窄屏（<900px）没有折叠式导航

- **现象**：480px 宽时侧栏变成 3 列网格，占满首屏，正文要向下滚一屏才出现；没有汉堡菜单。
- **判断**：桌面工具尚可接受，但「在笔记本小窗/平板上快速看一眼」的场景很难受。
- **严重程度**：低。

### 14. 表单控件风格不统一

- **现象**：附件是系统原生的亮色「选择文件」按钮；状态/优先级下拉比输入框明显更浅；部分下拉在 Windows Chrome 上原本是白底（已修，但同类问题在旧页面仍存在）。
- **判断**：整页看起来像两种设计拼在一起，降低「这是个成品」的感觉。
- **严重程度**：低。

### 15. 「API 文档」按钮在非开发环境会 404

- **现象**：右上角「API 文档」指向 `/docs` 新标签打开；但 `docs_enabled()` 为假时该路由不存在。
- **判断**：演示/生产环境点开是 404，且没有任何说明。
- **严重程度**：低。

### 16. 图标复用严重

- **现象**：「▤」同时用于「项目管理」和「工单管理」，「◎」同时用于「系统 AI 配置」「仪表盘」「模型中心」，「▥」同时用于「需求管理」「测试平台」。
- **判断**：靠图标扫视导航时无法区分，尤其旧页混在新页旁边时。
- **严重程度**：低。

## 四、附带观察（不是缺陷，但值得知道）

- **没有任何 console 报错、没有失败请求**：17 个路由逐页扫下来，`console.error` 与 `requestfailed` 都是 0，这点比多数内部工具干净。
- **项目选择记忆**在接口/UI 自动化页是生效的（选第 3 个项目 → 刷新后仍是第 3 个），说明 localStorage 方案本身没问题，只是没铺到所有页。
- **空态文案普遍存在**（「还没有模块，先建一个」「还没有账号，先添加一个」），比纯空白好，但都缺少「下一步该点哪」的按钮。
- **404 页本身做得不错**（有 404 标识、有解释、有返回按钮），只是返回目标选错了。

## 五、如果只修三件事

1. **把表单错误提示挪进弹窗**（发现 1）——这是新用户第一次操作就会撞上的墙。
2. **统一概览口径**（发现 2）——数据自相矛盾比功能缺失更伤信任。
3. **处理「开发工具」旧页**（发现 3）——加「旧版」标签或收进真正的开发者菜单，别和新功能平级。
