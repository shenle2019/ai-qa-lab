# 5 分钟演示脚本

> 线上地址：https://ai-qa-lab-production.up.railway.app/ui/
> 目标：在公网地址上完整走一遍“AI 生成用例 → 人工审核 → 服务端执行 → 查看报告”。

## 演示前

1. 打开一次站点预热。免费实例会休眠，首次访问可能需要 30-60 秒。
2. 如果现场要演示 AI 生成，先在 Render 环境变量里配置 `DEEPSEEK_API_KEY`；否则直接跳到执行环节，用种子数据里的两条 API 用例演示。
3. 准备一段需求文本，例如：

```
实现工单接口：GET /api/tickets 返回列表和 200；POST /api/tickets 创建工单，标题必填，成功返回 201，空标题返回 422。
```

## 演示步骤

### 1. 打开平台（30 秒）

访问 `/ui/`，说明这是同一套 FastAPI 同时托管接口和前端：`/docs` 是 OpenAPI，`/learning/` 是完整学习手册。

### 2. 建项目（20 秒）

进入“测试平台”，新建项目“现场演示”。说明项目是用例、计划、执行、缺陷的容器。

### 3. 模型中心（30 秒）

进入“模型中心”，展示模型列表、密钥掩码、调用记录。点“测试”验证连通性，指出每次调用都会记录耗时和 token。

### 4. AI 生成用例（60 秒）

回到“测试平台”，在用例卡片里粘贴需求，点“AI 生成用例”。展示生成结果：状态为 `draft`，来源标记为 `ai`，带 prompt 版本。

### 5. 审核门禁（60 秒）

挑一条点“提交审核”，再点“通过”；另一条点“驳回”。强调：只有 `approved` 的用例才可能被执行，前端绕不过后端校验。

### 6. 真实执行（60 秒）

新建计划“回归计划”，点“执行”。服务端会逐条发真实 HTTP 请求，记录每一步的状态码、耗时和失败原因。非 API 模块会明确标记为跳过。

### 7. 查看报告（30 秒）

在“最近执行”里点“查看报告”，展示通过率、总数、失败原因和逐条结果。

### 8. 边界说明（30 秒）

主动说明没做的部分：定时调度、分布式执行、权限体系、非 API 自动执行；SQLite 在免费实例重启后会重置。

## 兜底方案

如果 AI 生成不可用（未配置密钥、网络失败），直接执行种子数据：

1. 点击“加载演示数据”；
2. 进入计划“演示回归计划”，点“执行”；
3. 种子里的两条 API 用例会真实请求本服务，Web/App 用例显示跳过。

## 本地复现

```bash
bash scripts/start_sut.sh
# 浏览器打开 http://127.0.0.1:8000/ui/
```
