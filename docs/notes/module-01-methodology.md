# 模块 01 笔记：先选层，再动手

## 问题

测试新人最容易犯的错：拿到项目就想“要不要上 Playwright/Appium/压测/LLM 评测”，而不是先问“哪里最可能出事”。

工具不是方法论。方法论是先判断风险，再选测试层。

## 方案

一张原创的方法论页面，放在 `/ui/#/methodology`。

| 部分 | 内容 |
|---|---|
| 8 模块知识图谱 | 参考项目、star、license、核心能力、验收入口 |
| 5 层选型决策树 | 接口、Web、App、性能、LLM |
| 7 步协作流程 | 需求 → 风险 → 选层 → 数据 → 自动化 → 报告 → 回归 |
| 10 条检查表 | 交付前逐条过 |

## 结果

- 8 个模块卡片
- 5 个测试层
- 7 步流程
- 10 条检查表
- 页面：`/ui/#/methodology`
- 截图：`docs/portfolio/screenshots/module-01-methodology.png`

## 踩坑

1. 不要为了“看起来全”而全做，层越多维护成本越高。
2. 会工具不等于会策略。
3. 每层都要有可重复命令和报告，不能只留截图。
4. 风险判断要人拍板，AI 负责执行和整理。

## 一句话

测试策略的核心不是“我会多少工具”，是“我知道先测哪里、为什么、怎么证明”。
